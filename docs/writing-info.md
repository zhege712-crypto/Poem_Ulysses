# 可选写作信息：实现、迁移与验证

本地功能分支：`feature/optional-writing-info`，基于 `b791049b5ae60c735ad877cd287d4f568d56b544`。保留该基线的静态美术更新。本轮只做本地实现、隔离验证及提交，没有执行远程迁移、推送、合并或部署。

## 产品行为

投稿页和受保护编辑器提供默认收起的“写作信息（选填）”：起稿日期、完稿日期、写作地点，三项独立选填。日期接受 `YYYY`、`YYYY-MM`、`YYYY-MM-DD`，原样保留精度；不使用投稿、发表或修改时间补齐。地点为最多 200 字的普通文字，可用顿号描述多个地点，不请求定位权限、不保存 GPS。原作品日期、合集、子分类及目录排序规则继续独立使用。

两个日期均有值时，将年份或年月解释为可能日期范围。仅当起稿范围的最早一天晚于完稿范围的最晚一天时拒绝。例如 `2026-12 → 2026` 不拒绝，`2027 → 2026` 拒绝；校验范围不写回某个虚构的日期。有效公历日期、闰年、格式和地点长度由同一套浏览器／服务器规则校验。错误展开对应区块、定位字段并保留输入；日期恢复合法后清除该日期错误，不清除另外的服务或网络错误。

“在作品页公开这些写作信息”默认不勾选。完整信息供编辑者核对，公开预览另行标明实际效果。仅选择公开且作品／修订通过审核后，非空项目才在 `read.html` 正文末尾显示。全部为空时没有脚注占位；地点和长行在手机换行。已发表作品取消公开或清空，须按对应维护／修订流程生效。

普通匿名投稿人可在当前标签页核对输入；明确选择暂存后，`sessionStorage` 保留三字段及公开选择，不保存联系方式。私密状态链接仍只查询处理状态及撤回，不提供完整稿件读取。匿名稿件之后更正需联系维护者。邮件备用稿件包含所填写作信息及公开许可说明，由作者自行发送，不自动写入站内审核箱。

## 存储和公开边界

| 层 | 数据 | 访问与规则 |
| --- | --- | --- |
| `submissions.writing` | JSON 文本：`start`、`end`、`place`、布尔 `public` | 待审稿件的完整信息，仅原审核权限读取；普通状态查询 SELECT 不含此列 |
| `partner_works.writing` | 同上 | 固定 `partner_id` 的草稿；送审后读取审核稿最新值，版本和时间戳约束不变 |
| 合作稿件／修订历史 | 历史 JSON 中的规范化 `writing` | 沿用固定作品归属和最近 10 个版本；不根据笔名建立私稿权限 |
| `poem_writing` | `revision`、`poem_id`、完整 `data`、服务器 `created_at` | 已发表作品的私有不可变快照；没有按版本标识直接读取的 HTTP 接口 |
| 公开 `data/poems.json` | 可选 `writing: {start?, end?, place?}`；可选 `writingRevision` | `writing` 只包含明确勾选公开的非空值；`writingRevision` 是不含日期／地点的随机版本标识，不授予读取权限 |

受保护的 GitHub 读取路径按作品 ID 从 D1 补回完整信息，再交给既有维护者或固定作品归属校验后的合作账号。库级读取按最多 90 个版本标识分批，避免逐篇数据库请求。缺失快照或作品绑定不匹配时拒绝读取／保存，不把公开值猜作完整私有记录。

所有诗歌 GitHub 写入集中经过 `projectWriting`：先在 D1 暂存不可变完整信息，再把公开投影和随机标识提交至 GitHub。GitHub 文件 SHA 决定当前生效的版本；私有内容变动也改变版本标识，参加并发保护。失败或冲突产生的快照不会替换当前私有版本。修订另以作品内容哈希和版本号拒绝旧对照；哈希包含有意义的写作信息。旧稿无信息时保持原哈希结构，旧客户端漏传字段保留现值，明确传空对象才清空。

GitHub 提交信息、普通状态响应、公开 HTML 模板、审计摘要均不复制私有日期或地点。表单用 DOM／`textContent` 渲染；阅读脚注继续 HTML 转义。既有 Origin／CSRF、认证、限流、近期维护者登录、服务器字段白名单和审计失败拦截继续生效。没有新增账号授权范围、Secret 或第三方脚本。

## 保留、清空和删除

普通撤稿立即清空投稿的写作信息；合作撤稿同时清空草稿副本并删除稿件保存历史。未采用／撤回稿件 30 天后删除，长期未处理稿件 180 天后删除，已发表投稿副本的写作信息随正文、联系方式和内部备注于 30 天后清空。合作稿和修订历史沿用原清理规则；未送审草稿随本人删除清理，已结束修订及其对照／历史副本 30 天后清理。

当前作品引用的 `poem_writing` 快照随作品保留。未生效、被替换或作品删除后不再引用的快照，在创建满 30 天后由审核 Worker 每日任务清理。作品删除后，超过 30 天未更新的开放修订也会清空提议、对照及历史副本并结束状态；当前仍存在的作品修订保留。清空字段后，当前版本是明确的空信息；旧私有快照仍受保护并按上述规则清理。D1 恢复历史可能继续保留一段时间。

取消公开只能移除当前公开数据及页面中的相应字段。此前已经授权公开的内容可能仍在 Git 历史、缓存、搜索索引和他人副本；表单与隐私说明已如实说明，不能承诺从公开历史彻底消失。不要直接把旧公开诗歌 JSON 恢复到已清理的私有版本标识；如需恢复历史内容，应通过编辑器重新保存，并明确核对公开选择。

## 上线步骤（尚未执行）

1. 对 D1 做受保护的备份，确认原 `schema.sql`、`partners-schema.sql`、`security-schema.sql` 已存在。记录现有两 Worker 版本，备份不得进入公开仓库。检查 `PRAGMA table_info(submissions)`、`PRAGMA table_info(partner_works)` 及 `sqlite_master`，确认本迁移尚未应用。
2. **先执行一次增量迁移**：

   ```text
   wrangler d1 execute poem-submissions --remote --config submissions/wrangler.review.toml --file submissions/writing-schema.sql
   ```

   此文件只增加两列、一张表和索引，不改旧稿件值。`ALTER TABLE ADD COLUMN` 不可重复运行；若执行中断，先检查实际列／表状态，再执行缺少的语句，不盲目重跑。保留这张数据库与私有快照备份。
3. **先部署审核 Worker，再部署公开 Worker**：

   ```text
   wrangler deploy --config submissions/wrangler.review.toml
   wrangler deploy --config submissions/wrangler.public.toml
   ```

   审核配置和示例已设置 `keep_names = false`。共享浏览器函数通过服务端嵌入 nonce 脚本，此设置避免 Wrangler 注入的函数名称辅助代码令浏览器失效。保留当前 nonce CSP；不要为了这个组件放宽脚本策略。
4. 最后发布静态页面及 `writing-info.js`、`writing-form.js`、隐私说明。确认现有 40 篇作品、5 条日志的数据文件保持原样。旧稿只会看到空的新字段，不自动填日期。页面必须与 Worker 兼容后再让新字段进入投稿。
5. 维护者在可授权的验收稿件上核对普通投稿、合作账号及公开／取消公开效果；本轮没有使用线上数据进行这些操作。生产验收不应随意发表或删除真实作品。

回退保留新增列、表和全部私有记录；不得用初始化 SQL 覆盖数据库。启用后优先前向修复或部署支持此存储边界的已验证版本。回退至旧代码可能丢失新字段的保存与清理能力；应先暂停相关写入并核对待审稿／修订，不能只回退静态表单后假定私有记录仍受完整流程维护。

## 本地验证与预览

自动测试（Node 支持 `node:sqlite`）：

```text
node --test submissions/*.test.mjs
```

新增覆盖精度与明确倒序、有效公历日期、独立留空、迁移保存旧稿、匿名稿审核／发表／清理、固定合作归属、草稿和历史、公开／不公开／清空往返、旧客户端字段遗漏、SHA／时间戳／修订版本冲突、越权、XSS 格式、审计排除私有内容、D1 快照缺失时拒绝操作、批量读取绑定，以及 GitHub 已写入但 D1 完成标记失败后的幂等重试。
